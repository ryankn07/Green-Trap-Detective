# Full-screen phase transitions — 3 November 2026

The owner requested short, Quizizz-style full-screen transitions between game phases. The existing forest/paper identity remains: an emerald chapter for discussion, warm gold for secret actions, blue-green for reveal, and a faction-colored ending chapter. Each has a large Vietnamese phase heading, a line icon, the actual round number and a three-step phase trail. Rings and leaf accents accompany a vertical screen wipe.

New-project refinement: the first project and each new card/round use a dedicated emerald chapter with the original game logo, a large Green Trap Detective wordmark, animated branded card silhouettes fanning out, and the new project's public title/round. This replaces the discussion chapter on the same snapshot, so two screens never stack. It depends on the authenticated project's ID and round, not image-loading events or presence updates. Refresh into an existing project still skips the introduction. Original project/role artwork and private information remain untouched.

Ending refinement: a real `GAME_OVER` with winner `PROTECTOR` uses a dedicated green Good Ending chapter: sprout emblem, expanding light, hills and leaves. Winner `SABOTEUR` uses a red Bad Ending chapter: fractured emblem, contracting halo, dark skyline, smoke and rising embers. Each lasts 2 seconds and transitions onto the already-rendered ending/film. The shared faction outcome chooses the chapter for winners and losers alike. Draws retain the neutral chapter and never show a Good/Bad label or film. Presence snapshots retain both the current overlay and video element; a refresh does not replay the chapter.

`public/app.js` compares accepted authenticated snapshots by room, game ID, round and phase. It introduces the first round when a lobby starts, each real phase/round change, and game over. An initial snapshot into an existing game does not replay an introduction. Presence updates do not restart an animation. Rapid phase changes replace the current chapter rather than queueing outdated ones. Returning home, losing the session or hiding the page clears the overlay; background snapshots never queue a later animation.

The chapter is a cosmetic body-level overlay styled in `ui/style.css`, independent of the game grid and active on desktop/tablet/mobile. New state renders immediately. Pointer events pass through, keyboard focus is retained and the server clock continues normally. Old top-layer card previews close when the phase changes. No phase duration, action, polling interval or server behavior changes. Text uses only public phase/round data, without player roles, wallets or hidden actions.

The later [vote-out motion](ELIMINATION_EFFECT.md) follows the reveal chapter on the existing player tiles. If a successful expulsion ends the match, the accepted final state is cached and transport stops immediately; an inert board presents that two-second motion before the ending chapter. This is a presentation delay only, with no change to the authoritative phase or room cleanup.

The transition lasts 2 seconds, including entry and exit, following the owner's duration refinement. The owner subsequently requested the actual floating/entrance effects from the demo, rather than a longer static chapter. Phase-only animation declarations therefore override the global reduced-motion rule for the screen wipe, title entrance, rings and leaves. Other surfaces retain their reduced-motion behavior; no OS/browser setting is changed. A nearly expired phase skips or shortens the chapter, retaining at least 350 ms before its deadline. There is no fabricated countdown or sound/autoplay dependency.

Verification covers actual Node-server/SSE snapshots, lobby start, all phases, round changes, rapid replacement, same-phase identity and draft preservation, action input during the animation, card-dialog cleanup, refresh, session recovery, desktop/mobile bounds, short/landscape phone layouts, and reduced motion.
