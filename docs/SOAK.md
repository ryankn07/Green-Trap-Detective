# HTTP/SSE soak and recovery

Uses Node built-ins only. Run from the existing isolated checkout; no worktree or npm dependency is required. Baseline: `1fa143e12569170d817d3012349463c92f0c0838`. Unlike `load-smoke.cjs`, this runner uses wall time and a separate child process, without importing the room manager or accelerating phase deadlines.

```sh
node scripts/soak-http.cjs --report /tmp/soak-report.json
node scripts/soak-http.cjs --restart-at 300 --report /tmp/soak-recovery-report.json
node --test test/soak-http.test.cjs
```

Defaults: 50 sessions in one room, 600 seconds of steady load, 1-second health/action cadence. Setup, cleanup and deliberate restart/recovery time do not count toward the requested duration. A short explicit `--duration 5 --sessions 3 --restart-at 2` is useful for development; CI tests use short durations and never invoke the 10-minute default. Report files use exclusive creation: choose a new path for each run.

The child uses the current Node executable, a reserved ephemeral port (released immediately before spawn), a fresh temporary directory and its own `rooms.json`. Its environment contains only PATH, PORT and ROOM_STORE_PATH: no inherited application credentials, Supabase settings, production configuration or secret environment. No production endpoints are contacted by default. The small port allocation/spawn race is reported as startup failure rather than retried against another process. Cleanup only terminates the child it spawned and removes its own temporary directory. No repository source, existing snapshot or external resource is removed.

Each session authenticates independently and maintains an SSE stream. The host starts the real game after all sessions are connected. Statements and actions use gameId/round/phase from the latest sender snapshot, once per phase. Statements use UNSURE; blind actions spend nothing and use bankAction NONE. The runner uses real server deadlines, not clock overrides. It follows all phases encountered in the duration; a 600-second run does not imply ten rounds or game-over coverage. A context race, rejection or missing sender confirmation is a failure rather than silently discarded traffic.

The report contains aggregate counts and latency percentiles only. HTTP latency covers request through JSON response; sender-snapshot latency starts before submission and ends only when that sender's SSE projection confirms the statement/locked action in the same game/round. Values are milliseconds, with p50/p95/max and sample counts. They are separate measurements, not an assertion that response order equals SSE order. No percentile SLO is imposed. Reports omit snapshots, names, room/session identifiers, bearer tokens, response bodies, URLs and raw exceptions. Error codes are fixed/sanitized; child stdout/stderr are discarded to avoid leaking private state.

Health is checked throughout the load. Every stream must remain connected, receive bytes within 20 seconds (server heartbeat is 15 seconds), and have a fresh authenticated snapshot check at completion. Unexpected EOF, transport/protocol failure and revision regression are monitored. Reconnect uses exponential backoff (250ms base, four retries over the lifetime of a stream); exhaustion fails the run and CLI exits nonzero. A disconnected stream at a health iteration fails immediately, even if its reconnect is in progress: this is deliberately strict. Idle sleep alone cannot satisfy success. The final check requires all streams still connected. The initial/confirmation snapshot waits and HTTP operations have 10-second bounds.

`--restart-at N` deliberately closes streams, stops only the owned child, and starts a new child with the same snapshot path. It validates each existing token through `/api/state`, compares game identity, round, phase, own locked action and nondecreasing revision, then reconnects every SSE stream and checks its first snapshot. Intentional closes are counted separately from unexpected losses. Recovery verification covers these invariants, not byte-for-byte state equality: online flags, timestamps and revisions legitimately change. Restart close/start/readiness time is excluded from steady seconds. Restart near a real phase deadline can legitimately fail the strict phase comparison; schedule it away from boundaries when investigating persistence.

External targets require both `--base-url URL --allow-external`. This mode creates test rooms and leaves their lifecycle to the external operator, never kills that server or deletes remote data, and rejects restart. It is potentially load generating and must only be used on an explicitly authorized isolated test deployment. No external-target run was performed for this work.

Fast tests cover UTF-8/CRLF/multiline/chunked SSE, defaults and external opt-in, steady duration, real child restart/token recovery, stream/health false-pass prevention and report redaction. Optional browser tests are separate. An interrupted soak is not a pass; rely on the final JSON and process exit status. On executors that block localhost sockets inside the sandbox, use the supported execution permission flow rather than editing application code or disabling network/TLS protections.
